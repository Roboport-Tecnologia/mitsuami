mitsuami 1.0 is the first stable release: native, declarative, cross-platform UI for Rust.

You write one UI with signals, components and flexbox/grid layout. Each platform shows it with its own controls: AppKit on macOS, WinUI 3 on Windows, and GTK 4 on Linux, or Qt Quick with Kirigami for KDE Plasma. A button is an `NSButton` on macOS and a `gtk::Button` on GNOME, and it sizes and behaves as that platform's buttons do. mitsuami doesn't try to make platforms look the same.

```rust
use mitsuami::prelude::*;

fn hello() -> impl View {
    let clicks = signal(0);
    view! {
        <Column padding=Spacing::Xl gap=Spacing::Md>
            <Text>{move || format!("Clicked {} times", clicks.get())}</Text>
            <Button @click=move || clicks.update(|c| *c += 1)>"Click me"</Button>
        </Column>
    }
}

fn main() {
    App::new().window("Hello", Size::new(320.0, 160.0), hello).run();
}
```

```toml
[dependencies]
mitsuami = "1.0"

[dev-dependencies]
mitsuami-test = "1.0"
```

The backend is picked by the target OS. For KDE Plasma, use `default-features = false, features = ["kde"]`. Rust 1.95 or newer.

## What's in 1.0

- **Views** with `view!` or the builder API it expands to, and `#[component]` for components with typed props.
- **Fine-grained state**: `signal`, `computed`, effects, stores, `resource` for async data and `action` for async work. A component runs once; only what reads a signal updates.
- **Layout**: flexbox and grid with CSS semantics (Taffy), units like `px`, `em`, `%` and `fr`, and the platform's spacing tokens. HiDPI needs nothing from the app.
- **Widgets**: `Text`, `Button`, `ToggleButton`, `TextInput`, `PasswordInput`, `SearchInput`, `TextArea`, `Checkbox`, `Switch`, `RadioGroup`, `Slider`, `NumberInput`, `Select`, `Progress`, `Spinner`, `Separator`, `Image`, `Icon`, `FileIcon`, `ScrollView`, virtualised `List` and `Table`, `Group`, `Sidebar`, `Tabs`, `Toolbar`, `MenuButton`, menus, context menus, tooltips, windows and dialogs. [`ARCHITECTURE.md` §13](https://github.com/Roboport-Tecnologia/mitsuami/blob/v1.0.0/docs/ARCHITECTURE.md) lists the native control each one is on every platform.
- **Accessibility**: every widget has a role, name and value, and tests find widgets through them.
- **Localization** with Project Fluent (`locales!`, `t!`). Numbers and dates are written as the user's region writes them, and right-to-left languages mirror the app, native controls and window chrome included.
- **Desktop integration**: keyboard shortcuts and focus from code, hover, file drag and drop (in and out), the trash, launching files and URLs, and the platform's file icons.
- **Escape hatches**: `platform!` for per-platform code, `.native(tweak(…))` to set something on the native widget, `NativeView` to embed any `NSView`, GTK widget, QML item or XAML element, custom widgets, and `GpuSurface` for presenting with wgpu, Metal, Vulkan or Direct3D from the app's own thread.
- **Testing**: `mitsuami-test` finds widgets by role and text, clicks, types and asserts. The same test runs headless or on the real native widgets (`MITSUAMI_NATIVE=1`), with a controlled clock, scripted dialogs, tree, layout and wireframe snapshots, and stories captured at each size in light and dark. `cargo install cargo-mitsuami` adds `cargo mitsuami visual` to review and accept the captures.

## Platforms

| Platform | Backend | Needs |
|---|---|---|
| macOS 11+ | AppKit | Nothing else |
| Windows 10 1809+ (packaged apps) or 11 | WinUI 3 | The MSVC toolchain and the Windows App Runtime 2.4 or later |
| Linux (default) | GTK 4 | GTK 4.10+ and libadwaita 1.4+ |
| Linux (KDE Plasma) | Qt Quick + Kirigami | Qt 6.5+; at run time Kirigami 6.14+ and `qqc2-desktop-style` |

The test suite passes headless and natively on all four backends in CI. Every widget and service in the showcase has been tried by hand on each of them.

## Examples

Each widget has an example with a playground for its props: `cargo run -p mitsuami --example button`. There are also whole apps: `todos`, `contacts` (ten thousand rows in the platform's list control), `escape_hatches`, `files` (a simplified Finder on the real file system), `l10n` (five languages, Arabic right to left), and, as their own crates, `examples/showcase` and `examples/gpu-surface`.

## The showcase and Files

The showcase is every example in one window, picked from its sidebar. Files is a file browser on the real file system. Both are built for each platform:

- **macOS** (Apple silicon and Intel, macOS 11 or later): app bundles, signed ad hoc and not notarized. After unzipping, open the app once from Finder with Control-click → Open, or allow it in System Settings → Privacy & Security; or run `xattr -dr com.apple.quarantine <app>`.
- **Windows** (x86_64, Windows 11): needs the [Windows App Runtime 2.4 or later](https://aka.ms/windowsappsdk/2.5/latest/windowsappruntimeinstall-x64.exe). They aren't packaged, and Windows 10 runs WinUI apps only as packages.
- **Linux** (x86_64): AppImages, on GTK (`-gtk`) and on Qt Quick and Kirigami, as KDE Plasma's apps are (`-kde`). They bring their toolkit: the GTK ones need glibc 2.39 or later (Ubuntu 24.04 and newer), the KDE ones glibc 2.41 or later (Debian 13, Fedora 42, Ubuntu 25.04 and newer). Make one executable (`chmod +x`) and run it.
