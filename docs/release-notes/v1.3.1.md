mitsuami 1.3.1 fixes GTK on displays with a fractional scale, such as 160%.

## GTK

- **A `GpuSurface` renders at the display's own pixels on Wayland.** GTK's widget scale is a whole number, so on a 1.6 display the surface's buffer was made at 2x and the compositor shrank every frame by 0.8, which blurred fine detail such as a CRT shader's scanlines. The buffer is now sized by the fractional scale (`gdk_surface_get_scale`, GTK 4.12).
- **The platform metrics report the fractional scale.** `scale_factor` was the monitor's whole scale (2 on a 1.6 display), so pixels an app rendered for an image at that scale were shrunk on the way to the screen. It now comes from `gdk_monitor_get_scale` (GTK 4.14).

Both functions are looked up at run time, so the backend still builds and runs against GTK 4.10. An older GTK keeps the whole scale, as before.
