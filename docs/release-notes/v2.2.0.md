mitsuami 2.2.0 lets an app post the platform's own notifications, and tell the user it can't run in the platform's own error dialog, before it has a window or when it can't start at all.

## All platforms

- **Apps can post notifications** where the platform shows its apps': `notify(Notification::new(title).body(text).id(id))`. A later one with the same id replaces it, `withdraw_notification(id)` takes it away, and `on_notification_activated` tells the app which one the user clicked, once the platform has brought it forward. The reply says when the user turned the app's notifications off, where the platform tells. Tests see them through the scripted services (`notifications()`, `click_notification`), so nothing reaches the desktop.
- **`examples/notifications.rs` shows them.**
- **Apps can say why they can't start.** `mitsuami::fatal_error(title, message)` shows the platform's error dialog and returns once the user dismisses it. It needs no running app, so it works before `App::run` and when the app can't run at all, because an app started from its launcher has no terminal: what it writes to stderr goes to the journal or nowhere. Where there's nothing to show it on (GTK without a display, AppKit off the main thread) it returns at once, so apps should write the message to stderr too.
- **`examples/fatal_error.rs` shows it**: a viewer that can't start without a file.
- **An app can run without windows**, with `App::runs_without_windows()`: it starts with none if it likes, opens them as it needs, and ends when it calls `quit()`, because an app that waits for a notification's click or another process's request has nothing to show until then.

## macOS (AppKit)

- **The error is a critical `NSAlert`**, app-modal, with the app brought to the front for it, because there may be no window to put a sheet on. Launched from Finder it comes to the front. Launched from a terminal it stays behind and the Dock icon bounces, because since macOS 14 the terminal, still the active app, would have to give way.

- **Notifications go to Notification Center through `UNUserNotificationCenter`**, which asks the user the first time. The app has to be in a bundle, and not in a temporary folder, because macOS gives notifications only to an app it can find; outside a bundle `notify` answers that it's unavailable instead of raising an exception. As macOS does by default, the app in front gets no banner, only an entry in the list.

## Windows (WinUI)

- **The error is a Win32 `MessageBoxW` with an error icon**, because it needs neither the Windows App Runtime nor XAML, so it can show when the runtime is what's missing.
- **When the Windows App Runtime can't start, `run` says so in that message box**, naming the runtime and where to get it, before it panics as before, because a GUI app's panic goes nowhere.
- **The process is DPI aware before anything shows**, so the runtime's errors and the message box are sharp on a scaled display, not bitmap-stretched.
- **The message box has current controls**, from Common Controls 6, because without them Windows draws its unthemed Windows 2000 button, and a library can't put a manifest in the app's executable.

- **Notifications are the Windows App SDK's app notifications**, registered the first time the app shows one, and a click brings the window forward, restored if it was minimized. Where an unpackaged app can't register them, because only the full runtime installer adds the package they need, they're Windows' own toasts, as unpackaged Win32 apps show, so they show either way. A click after the app quit launches a packaged app again and does nothing for an unpackaged one.

## Linux (GTK and Kirigami)

- **GTK shows a parentless `gtk::AlertDialog`** with GTK's own Close button.
- **Kirigami shows a critical `QMessageBox`**, the dialog KDE's apps show with `KMessageBox::error`, with the title as its main text, because Plasma may show no text in its title bar.
- **GTK sends `GNotification`s** from a `GApplication` with the app's id, as GNOME apps do, and a click presents the window with the shell's activation token. It needs the app's id.
- **Kirigami sends notifications to the freedesktop.org notification server**, as KNotification does, with the app's `desktop-entry` so Plasma groups them, and a click raises the window with the server's activation token.
