mitsuami 2.1.0 tells an app when a window becomes the active one or stops being it, so a `GpuSurface` can stop the caret it paints, and lets C ABI apps decide whether a window closes.

## All platforms

- **Apps hear when a window becomes active or stops being it.** `Window::on_active_changed` reports it, its app going to the background included. The window keeps its focused control through this, so focus events can't tell an app that the window stopped taking keys.
- **A `GpuSurface` can stop its caret as a text field's does.** `GpuSurface::on_window_active` passes on the same change to the surfaces in the window, because a surface paints its own caret and keeps its focus while its window is inactive.
- **C ABI apps can ask about unsaved work before a window closes.** While `mitsuami_set_asks_before_closing` is on for a window, closing it only reports `CloseRequested`, and it stays until the app destroys it, as `Window::on_close_request` does in Rust. Windows still close by themselves unless an app turns this on.

## macOS (AppKit)

- **A window's activity comes from `windowDidBecomeKey:` and `windowDidResignKey:`**, so a window also stops being active when its app does.

## Windows (WinUI)

- **A window's activity comes from `Activated`**, reported only when it changes, because `Activated` also comes for a click on a window that's active already.

## Linux (GTK and Kirigami)

- **A window's activity comes from the toolkit's own signal**: `is-active` on GTK and `activeChanged` on Qt.

## For backend authors

- **`UiEvent` has a new variant, `WindowActiveChanged(bool)`.** The backend protocol stays exhaustive, so a backend or an exhaustive match outside this repository needs a new arm.
