mitsuami 1.3.6 closes dialogs on Escape in more places on macOS, and keeps a text field focused on Windows when it's opened from a menu or button.

## macOS (AppKit)

- **Escape closes a dialog with nothing focusable in it.** With the focus on the window itself, no view turned Escape into a cancel, and AppKit beeped instead of passing the key on, so the dialog stayed open. The backend's windows now close a dialog on Escape themselves.
- **A text field's surroundings hear Escape first.** AppKit's field editor sends Escape straight to the window, past the views round the field, so an `on_key` there, such as one that drops a label being edited, never heard it. Those views are now asked first, as they are for any other key the field doesn't use; a search field still clears on Escape.

## Windows (WinUI)

- **A field opened from a menu or button keeps its focus.** XAML reports focus changes late, so the focus going back from a closing menu, or leaving a button that went away, could arrive after the app had focused a new text field and read as the field losing focus: a field opened to rename in closed as it opened. The backend now reports what has focus when the event arrives.
