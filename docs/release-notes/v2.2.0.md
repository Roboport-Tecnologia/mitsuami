mitsuami 2.2.0 lets an app tell the user it can't run, in each platform's own error dialog, before it has a window or when it can't start at all.

## All platforms

- **Apps can say why they can't start.** `mitsuami::fatal_error(title, message)` shows the platform's error dialog and returns once the user dismisses it. It needs no running app, so it works before `App::run` and when the app can't run at all, because an app started from its launcher has no terminal: what it writes to stderr goes to the journal or nowhere. Where there's nothing to show it on (GTK without a display, AppKit off the main thread) it returns at once, so apps should write the message to stderr too.
- **`examples/fatal_error.rs` shows it**: a viewer that can't start without a file.

## macOS (AppKit)

- **The error is a critical `NSAlert`**, app-modal, with the app brought to the front for it, because there may be no window to put a sheet on. Launched from Finder it comes to the front. Launched from a terminal it stays behind and the Dock icon bounces, because since macOS 14 the terminal, still the active app, would have to give way.

## Windows (WinUI)

- **The error is a Win32 `MessageBoxW` with an error icon**, because it needs neither the Windows App Runtime nor XAML, so it can show when the runtime is what's missing.
- **When the Windows App Runtime can't start, `run` says so in that message box**, naming the runtime and where to get it, before it panics as before, because a GUI app's panic goes nowhere.
- **The process is DPI aware before anything shows**, so the runtime's errors and the message box are sharp on a scaled display, not bitmap-stretched.
- **The message box has current controls**, from Common Controls 6, because without them Windows draws its unthemed Windows 2000 button, and a library can't put a manifest in the app's executable.

## Linux (GTK and Kirigami)

- **GTK shows a parentless `gtk::AlertDialog`** with GTK's own Close button.
- **Kirigami shows a critical `QMessageBox`**, the dialog KDE's apps show with `KMessageBox::error`, with the title as its main text, because Plasma may show no text in its title bar.
