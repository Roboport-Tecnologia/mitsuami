mitsuami 2.5.0 lets an app open its windows as the user left them, where they were and at the size they had, maximized or not, the way each platform's own apps save and restore them.

## All platforms

- **`Window::frame(signal)` keeps a window's restored frame**, its content size and where it is, so an app saves it as the window closes and hands it back to open the window as it was left. The platform fills it in as the window shows and as the user moves or resizes it, but not while it's maximized, minimized or in full screen, so maximizing doesn't lose it, and set then, it's the frame the window goes back to. A frame on a display unplugged since comes back onto a screen, no larger than its work area, as the platforms' own restores do. Its position is in the platform's own coordinates, a value to hand back, not to compute with, and `None` where a window can't know where it is (GTK 4, Wayland).
- **`Window::placement(Placement::Centred)` centres a window no frame placed**, and `Ui::centre_window` centres one now, because an app opening for the first time has no frame to restore and the platform's place for a new window may be a corner.
- **`WindowSize::Screen { width, height }` sizes a window to fractions of its screen's work area**, and `Ui::work_area` gives that area to apps, so a first window fits the screen it opens on instead of a size picked for another.
- **A window whose content sets its height keeps it** when a frame opens it: the frame gives only its width and where it is.

## macOS (AppKit)

- **A window that opens zoomed stays zoomed**, and its size is the frame it un-zooms to, because the size was applied after the zoom while the window was still hidden, un-zooming it into the screen's top-left corner, reported as not maximized.
- **A zoom's animation is no longer reported as the restored frame**, because its last step before it counted as zoomed was nearly as large as the screen, and an app keeping that frame reopened its window short of the screen's right and bottom edges.
- **`Placement::System` and `Centred` are the same**: AppKit already centres every new window, its own place for one being the screen's corner.

## Linux (GTK and Kirigami)

- **GTK keeps and restores a window's size only**, because GTK 4 has no way to move a window and the compositor places it, as it does for every GTK app; a frame's position is `None` there.
- **Kirigami restores where a window was on X11 too**, onto the nearest screen, and its size alone on Wayland, where no client can place its windows.

## Windows (WinUI)

- **Windows open with the system's opening animation**, because a window's first show was spent at creation, invisibly, and Windows animates only a window's first show.
- **A window that opens maximized shows maximized at once**, laid out at its maximized size while still hidden, instead of growing from its restored size or drawing a first frame at the wrong size, and its GPU surfaces report no size until it shows, so an app draws its first frame at the size the window shows at.
- **A window asked to open maximized stays maximized**, because sizing it before its first show was read as the user restoring it.
- **A window flush against a screen's edge reopens there**, because what's kept on the screen is its visible frame, not its invisible resize borders.
